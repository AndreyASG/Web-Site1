# ASG CODE - сайт V1

Одностраничный коммерческий сайт студии ASG CODE. Чистые HTML, CSS и JavaScript, без фреймворков и без установки зависимостей.

Фирменный стиль: `../brand-design/asg-code/approved/brand-guide.md`. Логотипы скопированы в `assets/brand/` без изменений.

## Как открыть на компьютере

```bash
cd "D:/2026 Web sait/asg-code-site"
python -m http.server 47920 --bind 127.0.0.1
```

Затем открыть в браузере: http://127.0.0.1:47920

| Путь | Что внутри |

## Что заменить перед публикацией

1. **Контакты** - в `index.html`, блок с комментарием `ЗАМЕНИТЬ перед публикацией`: телефон `+7 (000) 000-00-00`, Telegram `@your_telegram`, почта `mail@example.ru` (сейчас это заглушки).
2. **Отправка заявок** - в `js/main.js` переменная `FORM_ENDPOINT`. Пока она пустая, форма проверяет поля и честно пишет посетителю, что работает в демо-режиме. Укажите адрес обработчика (вебхук Telegram-бота, CRM), и форма начнёт отправлять заявки в формате JSON: `name`, `contact`, `service`, `message`, `agree`.
3. **Политика обработки персональных данных** - форма собирает имя и контакт, поэтому по 152-ФЗ нужна страница политики и ссылка на неё рядом с галочкой согласия. Её пока нет.
4. **Примеры работ** - в `assets/portfolio/` замените `specialist.svg`, `small-business.svg`, `automation.svg` реальными скриншотами (лучше 1200×800, формат `.webp` или `.png`; при смене расширения поправьте путь в `index.html`). Подписи «Пример дизайна» уберите, когда появятся настоящие кейсы.

## Версия V3 - утверждённый ноутбук-изображение

Открыть: http://127.0.0.1:47920/v3.html. V3 - копия V2 (тот же «дождь данных» и все блоки), но на первом экране вместо нарисованного CSS-ноутбука стоит утверждённое изображение. Файл `v3.html` подключает `css/hero-photo.css` и `js/hero-v2-photo.js`; V2 (`v2.html`) по-прежнему подключает `css/hero-laptop.css` и `js/hero-v2.js`.

### Ноутбук-изображение и сценарий (V3)

На утверждённом изображении карточки «Новая заявка» и «ИИ-помощник» уже нарисованы. Чтобы не было двойного наложения, живые HTML-карточки лежат точно поверх нарисованных и полностью их закрывают. Карточки всегда на месте, а сценарий меняет их состояние (~11 секунд на цикл):

1. Карточка заявки: «Сайт «Север» - Ждём новую заявку»; ИИ: «ждёт заявку».
2. Курсор подъезжает к кнопке «Оставить заявку» на экране ноутбука и нажимает её, кнопка вспыхивает.
3. Карточка заявки вспыхивает и меняется на «Новая заявка - Ирина, ремонт ванной, +7 912 *****48».
4. Карточка ИИ вспыхивает, статус «пишет ответ», ответ печатается по буквам.
5. Статус «✓ Отправлено», затем обе карточки возвращаются в режим ожидания.

Координаты карточек и кнопки - в `css/hero-photo.css` (проценты от размеров изображения), тайминги - в `cycle()` в `js/hero-v2-photo.js`. На смартфоне карточки шире (чтобы текст читался) и по-прежнему закрывают нарисованные. Скриншоты: `screenshots/v2-photo-*.png`.

### Нарисованный CSS-ноутбук (V2)

Сценарий на ноутбуке (повторяется каждые ~11 секунд): на экране открыт сайт клиента (пример - «Север», ремонт квартир) → курсор посетителя подъезжает к кнопке «Оставить заявку» и нажимает её → справа на экране выезжает уведомление «Новая заявка» → рядом появляется карточка «ИИ-помощник» и печатает ответ клиенту → статус «Отправлено» → всё уходит. Тайминги - в функции `cycle()` в `js/hero-v2.js`, текст ответа - в `v2.html` (блок `aireply__text`). Размеры внутри экрана заданы в `cqw` (доля ширины экрана), поэтому «сайт» на ноутбуке чёткий на любом размере. Сценарий на паузе, когда первый экран не виден или вкладка скрыта; при «уменьшить движение» уведомление и готовый ответ просто стоят.

Скриншоты сцены: `screenshots/v2-laptop-01-click.png`, `v2-laptop-02-typing.png`, `v2-laptop-03-done.png`, `v2-laptop-mobile.png`. Скриншоты `v2-desktop-02…05` показывают прежний вариант с макетом браузера.

Настройки в `css/data-rain.css`:
- цвета линий `--dr-calm`, `--dr-mid`, `--dr-hot` - фирменные синий, голубой и циан (в исходном компоненте были циан, фиолетовый и розовый);
- яркость `--dr-brightness` (сейчас 2.2): меньше - спокойнее, больше - заметнее;
- свечение `--dr-bloom-opacity`, `--dr-bloom-blur`.

Количество линий и скорость - в конце `js/data-rain.js` (`count`, `flowSpeed`, `obstacleRadius`).

Поведение:
- на компьютере около 2 500 линий (зависит от размера экрана), на телефоне 1 800; при слабом устройстве количество само снижается;
- когда первый экран прокручен и не виден, анимация останавливается и не тратит ресурсы;
- при настройке системы «уменьшить движение» рисуется один статичный кадр без анимации.

Важно: ТЗ V1 запрещает «бесконечные анимации, отвлекающие от содержания». V2 - эксперимент по вашей просьбе; поэтому эффект ограничен первым экраном, приглушён под текстом и останавливается вне экрана.

### Почему не React-компонент как есть

Компонент написан для React + TypeScript + Tailwind + shadcn, а сайт - на чистом HTML/CSS/JS без сборки (так задумано ТЗ: без тяжёлых фреймворков). Поэтому код перенесён на чистый JavaScript без изменений в физике и отрисовке. В присланном CSS не было стилей самих слоёв (`.dr-root`, `.dr-bloom`, `.dr-vignette`, `.dr-grain`) - они дописаны в `css/data-rain.css`.

Если сайт когда-нибудь переедет на React, порядок такой:

```bash
npm create vite@latest asg-code-react -- --template react-ts
cd asg-code-react
npm install tailwindcss @tailwindcss/vite
npx shadcn@latest init
```

После `shadcn init` компоненты кладутся в `src/components/ui/` - это стандартная папка shadcn: её ожидают CLI (`npx shadcn add ...`) и импорт `@/components/ui/...`, поэтому компоненты должны жить именно там. Туда копируется `data-rain.tsx`, а переменные и стили - в `src/index.css`.
